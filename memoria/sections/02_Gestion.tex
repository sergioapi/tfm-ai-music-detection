\section{Introducción}

Este capítulo presenta los objetivos del TFM, la metodología de trabajo, la planificación temporal y el presupuesto estimado del proyecto. Estos elementos establecen el marco de organización y seguimiento aplicado durante su desarrollo.

\section{Objetivos}

\subsection{Objetivo general}

Comparar un enfoque clásico basado en MFCC y SVM con un enfoque profundo basado en MERT congelado y SVM para la detección de música generada mediante inteligencia artificial, evaluando ambos mediante medidas predictivas y operacionales bajo un diseño experimental común.

\subsection{Objetivos específicos}

\begin{enumerate}
    \item Revisar el estado del arte relacionado con la detección de música generada mediante IA.
    \item Auditar y preparar AIME para su uso experimental.
    \item Definir un protocolo reproducible de particionado, preprocesamiento y evaluación.
    \item Seleccionar, implementar y evaluar un baseline clásico basado en MFCC y SVM.
    \item Seleccionar, adaptar y evaluar un enfoque profundo basado en MERT y SVM.
    \item Comparar ambos enfoques y seleccionar el modelo más adecuado para la prueba de concepto, considerando conjuntamente su rendimiento predictivo y su viabilidad operacional.
    \item Desarrollar y desplegar una prueba de concepto web que integre el modelo seleccionado.
    \item Documentar decisiones, experimentos y artefactos para garantizar la reproducibilidad.
\end{enumerate}

\section{Metodología}

El proyecto sigue un desarrollo iterativo e incremental organizado mediante fases, issues y ciclos de trabajo breves. Esta forma de trabajo permite dividir el TFM en tareas manejables, revisar los resultados de cada etapa y mantener trazabilidad entre decisiones, experimentos y artefactos generados.

\subsection{Documentación y revisión bibliográfica}

La memoria se redacta en LaTeX mediante Overleaf, manteniendo una estructura de capítulos coherente con los requisitos del TFM. La revisión bibliográfica se organiza de forma estructurada y trazable, de modo que las fuentes empleadas puedan relacionarse con las decisiones metodológicas y con el estado del arte descrito en la memoria.

\subsection{Gestión del proyecto y control de versiones}

El desarrollo se gestiona con Git y GitHub, utilizando ramas e issues para separar tareas y registrar cada bloque de trabajo. Las decisiones relevantes, los experimentos ejecutados y los artefactos producidos se documentan en el repositorio para facilitar su revisión posterior.

\subsection{Preparación de los datos y reproducibilidad}

La preparación experimental parte de la selección y auditoría de AIME como conjunto de datos principal. Antes del procesamiento de audio se generan particiones reproducibles. El manifiesto se divide en \textit{train}, \textit{val} y \textit{test}, correspondientes respectivamente al ajuste del modelo, la selección de la configuración y la evaluación final. Esta separación permite controlar fugas de información y mantener el mismo conjunto de datos para evaluar los dos enfoques comparados.

\subsection{Desarrollo y evaluación experimental}

Los modelos se evaluaron bajo el procedimiento definido durante la preparación de los datos. Los experimentos se ejecutaron en el entorno virtual del proyecto, configurado con Python 3.11.9. Durante el proceso se registraron medidas predictivas y operacionales, y la reproducibilidad se apoyó en artefactos estructurados y pruebas automatizadas sobre los componentes críticos.

La metodología experimental distingue entre cuatro formas de abordar la clasificación: características manuales con aprendizaje automático clásico, embeddings de un modelo profundo congelado con un clasificador supervisado, fine-tuning parcial y fine-tuning completo. En el desarrollo realizado se ejecutaron las dos primeras. El baseline utilizó MFCC con una SVM, mientras que el enfoque profundo empleó MERT como encoder congelado para obtener embeddings y entrenó después una SVM sobre esas representaciones.

Las principales dependencias entre las fases son las siguientes:

\begin{itemize}
    \item La auditoría de AIME y la generación de las particiones preceden a la ejecución de los experimentos.
    \item El baseline y el modelo profundo deben evaluarse mediante el mismo procedimiento antes de realizar la comparación.
    \item La selección del modelo para la aplicación depende de los resultados predictivos y operacionales de ambos enfoques.
    \item La implementación web requiere el artefacto y el preprocesamiento del modelo seleccionado, mientras que las pruebas y el despliegue preceden al cierre del proyecto.
\end{itemize}

\section{Presupuesto}

El presupuesto estima el coste económico asociado al desarrollo del TFM durante las 300 horas de dedicación planificada. Su finalidad es valorar el esfuerzo y los recursos necesarios para el trabajo académico, por lo que distingue entre costes imputados, como la dedicación, la amortización del hardware, la electricidad y la conexión a Internet, y costes directos de herramientas, servicios y datos. Se interpreta como una estimación presupuestaria del proyecto académico.

\subsection*{Recursos humanos}

Para valorar la dedicación se toma como referencia el coste laboral medio por hora efectiva publicado por el Instituto Nacional de Estadística para el primer trimestre de 2026, de 24,88~\euro{}/h~\cite{ineETCL1T2026}. Aplicado a las 300 horas planificadas, el coste imputado de los recursos humanos asciende a 7.464,00~\euro{}.

\[
    300~\text{h} \times 24{,}88~\text{\euro{}/h} = 7{.}464{,}00~\text{\euro{}}
\]

\subsection*{Recursos materiales, suministros y comunicaciones}

La amortización del hardware se calcula a partir de precios estimados representativos y de una vida útil de cuatro años. Esta vida útil equivale a una amortización lineal anual del 25~\%, porcentaje que coincide con el coeficiente lineal máximo indicado por la Agencia Tributaria para equipos destinados a procesos de información \cite{aeatCoeficientesAmortizacion2025}. El coste imputado al TFM se obtiene aplicando el periodo de 86 días mediante la expresión:

\[
    \text{coste amortizado} = \text{precio estimado} \times \frac{86}{4 \times 365}.
\]

El coste eléctrico se estima con una potencia media de 0,12~kW para el conjunto formado por el portátil, el monitor y los periféricos. Se trata de un supuesto de consumo medio, no de una medición directa. Como precio de referencia se utiliza 0,2669~\euro{}/kWh, correspondiente a Eurostat para España durante el segundo semestre de 2025, con impuestos incluidos y banda doméstica de 2.500 a 4.999 kWh \cite{eurostatNrgPc2042025S2}:

\[
    0{,}12~\text{kW} \times 300~\text{h} \times 0{,}2669~\text{\euro{}/kWh} = 9{,}61~\text{\euro{}}
\]

La conexión a Internet se valora mediante una cuota doméstica representativa de 30,00~\euro{} mensuales. Para el periodo imputado de 86 días, equivalente a 2,827 meses, el cálculo se realiza de forma proporcional sobre el año completo:

\[
    30{,}00 \times \frac{86}{365} \times 12 = 84{,}82~\text{\euro{}}
\]
